## Why

Удаление карточки уже предусмотрено клиентом, но сервер пока не обрабатывает DELETE-запросы. Без серверного контракта карточка не удаляется из набора данных, а ошибки и неизвестные маршруты могут возвращать неструктурированные ответы.

## What Changes

- Добавить `DELETE /cards/:id`: удалять карточку по идентификатору из URL и отвечать `204` при успехе.
- Возвращать JSON с описанием ошибки и статусом `404`, если карточка не найдена или маршрут неизвестен.
- Добавить финальный error middleware, который возвращает JSON и статус `500`.
- Сохранить существующий формат карточек и совместимость с клиентским DELETE-запросом.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `card-deletion`: определить серверный контракт удаления карточки и JSON-ответы для ошибок.

## Impact

- Серверный маршрут и middleware в `server/index.ts`.
- Существующий контракт удаления карточек `openspec/specs/card-deletion/spec.md`.
- Клиент использует `DELETE /api/cards/:id` через существующий proxy; файлы `client/` не изменяются.
