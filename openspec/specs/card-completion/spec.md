# card-completion Specification

## Purpose
Определяет изменение признака `isDone` карточки и серверный контракт обновления статуса выполнения.

## Requirements

### Requirement: Отметка карточки выполненной
Система SHALL предоставлять пользователю возможность отметить карточку выполненной и снять отметку. Сервер SHALL принимать изменение признака `isDone` запросом `PATCH /cards/:id` с телом `{ "isDone": boolean }`. Middleware SHALL отклонять отсутствующее или не boolean значение `isDone` ответом `400` до вызова контроллера. Если карточка с указанным `id` не найдена, контроллер SHALL отвечать `404`. При успешном изменении сервер SHALL сохранять новое значение `isDone` у карточки и отвечать `200` с полным обновлённым представлением карточки в JSON. Изменённое состояние SHALL оставаться после повторной загрузки доски.

#### Scenario: Отметить карточку выполненной
- **WHEN** клиент отправляет `PATCH /cards/:id` с телом `{ "isDone": true }` для существующей невыполненной карточки
- **THEN** сервер сохраняет `isDone: true`, отвечает статусом `200` и возвращает JSON обновлённой карточки с тем же `id` и `isDone: true`, а доска отображает карточку как выполненную

#### Scenario: Снять отметку выполнения
- **WHEN** клиент отправляет `PATCH /cards/:id` с телом `{ "isDone": false }` для существующей выполненной карточки
- **THEN** сервер сохраняет `isDone: false`, отвечает статусом `200` и возвращает JSON обновлённой карточки с тем же `id` и `isDone: false`, а доска отображает карточку как невыполненную

#### Scenario: Отклонить неверное значение isDone
- **WHEN** клиент отправляет `PATCH /cards/:id` с не boolean значением `isDone`, например строкой `"true"`
- **THEN** middleware отклоняет запрос до вызова контроллера, сервер отвечает статусом `400`, а состояние карточки не изменяется

#### Scenario: Отклонить отсутствующее значение isDone
- **WHEN** клиент отправляет `PATCH /cards/:id` без поля `isDone`
- **THEN** middleware отклоняет запрос до вызова контроллера, сервер отвечает статусом `400`, а состояние карточки не изменяется

#### Scenario: Изменить несуществующую карточку
- **WHEN** клиент отправляет `PATCH /cards/:id` с boolean значением `isDone` для отсутствующего `id`
- **THEN** сервис сообщает, что карточка не найдена, а контроллер отвечает статусом `404` с JSON-описанием ошибки

#### Scenario: Сохранить состояние после обновления доски
- **WHEN** клиент успешно изменяет `isDone` существующей карточки и затем повторно загружает список карточек
- **THEN** ответ `GET /cards` содержит эту карточку с сохранённым значением `isDone`
